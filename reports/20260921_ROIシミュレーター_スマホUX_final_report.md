## 3. 設計上の重要な判断

### 3-1. 「入力中も結果を常時表示」を意図的に諦めた

当初の設計は「画面下部に3値を固定表示し、入力中も常時可視」だった。Codex astra の設計チェックで次が判明し、設計を変更した。

- **iOS Safari では `position: fixed; bottom: 0` がキーボードの上に来る保証がない**。レイアウトビューポートが縮むとは限らず、固定要素が隠れる場合がある
- **Playwright はソフトキーボードを再現できない**ため、「見えている」ことを検証する手段がない＝**検証不能な AC** だった

変更後:

| 場面 | 表示 |
|---|---|
| 入力セクション直後 | 3値＋前提の要約を**通常フロー**で表示（遮蔽リスクなし） |
| 入力を眺めている間 | 下部に「年間効果差額（試算）」**1値**＋「結果を見る」 |
| キーボード表示中 | 固定バーを**退避**（隠れた状態で「見えているはず」の表示を残さない） |
| 結果を見ている間 | 「入力に戻る」で直前に操作した欄へ戻る |

固定表示を1値に絞ったのは、初年度費用が固定である以上、年間効果差額と ROI の情報がほぼ重複するため。

### 3-2. 仕様の誤りを6件、実測で訂正した

| 項目 | 当初の記述 | 実測 |
|---|---|---|
| 前提の常時表示 | 「畳んでも `.summary-assumptions` に残る」 | **誤り**。料金も「提案2倍」も載っていない → 折りたたみ見出し自体に要約を出す形へ |
| 距離短縮の手段 | 「計算の前提を畳めば距離が縮む」 | **誤り**。`.premise` は結果バナーより後ろにあり、距離には1pxも寄与しない |
| 案件0件のとき | 「投資回収は `—`」 | **誤り**。実際は **13.6ヶ月**（工数削減ぶんの効果は残る） |
| 年商の検証 | 「全入力で結果が更新される」 | **誤り**。年商は計算に不使用。逆に「変わらないこと」を確認すべき |
| 印刷の検証 | 「バーの文字列が出ない」 | 印刷サマリー側の正当な同じ文言まで不合格になる → 要素ベースの検査へ |
| viewport | 「完全不変」 | セーフエリア対応と両立しない → `viewport-fit=cover` のみ許容に限定 |

加えて、**全角数字は空にならず Chrome が半角に正規化する**こと、**マイナス入力でバー幅は崩れない**ことを実測で確認し、仕様書 §4.2.1 に記録した。

### 3-3. 検証手段を3種に分類した

Playwright の端末エミュレーションは viewport・タッチ・UA を再現するだけで、実機の OS キーボードや Safari の操作領域は再現しない。すべてを自動検証で証明できないため、仕様書 §5.0.1 で **自動判定 / 実機確認 / 設計評価** に分けた。

## 4. 残課題

### 4-1. 実機でしか確認できない項目（未検証）

| 項目 | 状態 |
|---|---|
| iOS の自動ズームが実際に止まったか | 前提条件（全入力 16px 以上）は機械検証済み。実挙動は**未検証** |
| ソフトキーボードによる遮蔽と固定バーの振る舞い | 退避処理の動作は検証済み。実機の挙動は**未検証** |
| セーフエリア（ホームインジケータ）との重なり | CSS 宣言の存在のみ確認。`env()` は Playwright で 0 を返す |
| URL バー伸縮時の固定バーの挙動 | **未検証** |
| 小数点キーが実際に出るか | 属性付与のみ確認 |
| 全角数字入力の iOS 実機挙動 | Chrome の挙動のみ確認 |
| 削除時の固定バー復帰（Safari 系） | Chromium では再現せず。**WebKit が環境に無く未検証** |

### 4-2. Codex の P2 指摘（今回未対応）

| # | 内容 | 判断 |
|---|---|---|
| 1 | 固定バーの状態管理が `focusin`/`focusout` のみ。`pageshow`・Window フォーカス復帰・`select` 確定が未処理 | 実機での挙動確認が先。UA 依存のため推測で足さない |

| 4 | 極端に長い金額（桁数が十分大きい場合）の包含 | 現在 +98億9,871万円まで溢れないことを実測。入力上限の仕様化は別途 |
